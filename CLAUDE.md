## Folder structure
| Folder | Contents |
|---|---|
| `inputs/` | Sources: `<id>.txt` (text exactly as it will be shown, one paragraph per line) + `<id>.meta.json` (title, source URL, what was edited) |
| `lex/` | Shared lexicon for all texts: `lemmas.json`, `forms.json`, `names.json` + annotation batches `parts/partN.{forms,lemmas,names}.json`; `phrases/<id>.json` = expressions per text; `overrides/<id>.json` for per-occurrence fixes; `missing_<id>.tsv` = words still to annotate (generated) |
| `texts/` | Built texts `<id>.json` (generated, format in `texts/README.md`) |
| `app/` | The web app: `index.html`, `app.js`, `style.css`; `data/*.js` generated by the build |
| `tools/` | `build_text.py` (build + validate), `conjugate.py` (verb engine, self-test), `validate_text.py`, `check_part.py`, `publish_texts.py` (upload texts to Supabase), `test_sync.js` (two-device merge test), `cloud_test.html` + `fake_supabase.js` (the app against an in-memory fake Supabase; generated from `app/index.html`) |
| `supabase/` | `schema.sql` — tables `texts`, `progress` with row-level security |

Root: `CLAUDE.md`, `SPEC.md`, `SETUP.md` (user's one-time setup guide), `.env.example`, `.gitignore`.

## Git & publishing
Local git repo, branch `main`; remote `origin` = github.com/yacheater/spanishbookreader (the user's **personal**
account; commits as `yacheater` / its noreply address — repo-local config, never the work email).
**Deploy** = publish the `app/` folder to the `gh-pages` branch (GitHub Pages source = `gh-pages` / root):
`git push origin main && git subtree push --prefix app origin gh-pages` — site updates in ~1 min.
(No Actions workflow: pushing workflow files needs an extra `workflow` token scope.)
**Never committed** (`.gitignore`): `inputs/`, `texts/*.json`, `app/data/` — full copyrighted texts — and `.env`
(Supabase service_role key; never print it, never ask for it in chat). Texts reach the deployed app only through
`python3 tools/publish_texts.py` → private Supabase table. `app/config.js` holds the public URL + anon key.

## Adding a text («обработай …»)
1. Put the text into `inputs/<id>.txt` — **verbatim**, one paragraph per line; write `inputs/<id>.meta.json`.
   Websites behind a bot check (cultura.gob.ar, scielo.cl) can't be fetched — ask the user to paste the text.
   **Scientific articles:** drop navigation and reference/bibliography blocks; replace the methodology
   section with a short Spanish summary (keep research questions verbatim); say so in `meta.edited`.
   Everything else stays word for word.
2. `python3 tools/build_text.py <id>` → `lex/missing_<id>.tsv` lists words not in the lexicon
   (the shared lexicon already covers ~1,100 forms, so later texts need less).
3. Annotate the missing words into a new `lex/parts/partN.*.json` following `lex/ANNOTATION.md`
   (large lists → split and annotate in parallel), check with `python3 tools/check_part.py N lex/missing_<id>.tsv` until OK.
4. Mark multi-word expressions in `lex/phrases/<id>.json` (idioms, collocations, grammar constructions —
   NOT plain connectors; format and rules in `lex/ANNOTATION.md` → «Phrases»).
5. Rebuild; done when it prints `missing 0`, no `!` problems and `validate: OK`.
6. If Supabase is set up (`.env` exists): `python3 tools/publish_texts.py <id>` so the text shows up on the phone.

Grammar (tense/person, number, gender, conjugation tables) is computed by `tools/conjugate.py`
— never typed by hand. After changing it run `python3 tools/conjugate.py` (self-test).

## Running the app
- Deployed: `https://yacheater.github.io/spanishbookreader/` (cloud mode: sign-in, texts from Supabase, sync).
- Local: `python3 -m http.server 8765 --directory app` → http://localhost:8765 — cloud mode if `app/config.js`
  is filled in, otherwise local mode (texts from `app/data/*.js`, progress only in this browser).
- After changing sync code: `node tools/test_sync.js`; UI against the fake: serve the project root and open
  `/tools/cloud_test.html` (test password `correct-horse`).
- Bump `?v=N` on the asset links in `app/index.html` after changing app files (phones cache aggressively).
